General GP
• General structure of the GP algorithm:
   • Generate initial population of random programs
   • Evaluate the programs by running them and test on data
   • Generate new population of programs:
      • Selection based on fitness
      • Crossover of two programs
      • Mutation of programs
   • As usual, repeat until a good enough solution is found

Tree-based GP
• John Koza, late 80s-early 90s:
• Programs are represented as syntactic trees
• Terminals are variables and constants
• Non-terminals are operations
• Crossover is a subtree exchange, non-terminals have typically bigger
  probability to be a crossover point
• Mutation replaces a subtree with random one
• Fitness is determined by running the program
• Selection is standard, often tournament
• First examples in Lisp

Initializations
  • Random procedure how to generate trees from two sets – terminals and non-
    terminals
  • Grow: Generate random trees from both sets till a limit on number of nodes
    is reached
  • Full: Generate random trees from non-terminal till certain depths, then only
    terminals are added
  • Ramped half-and-half: half of population by grow, half by full

Mutations
• It is good (almost necessary) to use more mutation types:
   • Random or systematic mutation of constants
      • GP traditionally had problems fine-tuning numerical values
      • Thus, a specialized mutations of constants speed-up the algorithm
      • Either (any) arithmetic mutation on constants
      • Or iterations of hill-climbing or other optimization methods on one or all constant set of
        the tree
   • Random exchange of a node for the same arity one
   • Permutations
   • Swap non-terminal for terminal
   • Mutations that decrease the size of the tree (smaller sub-tree, new individual
     from a sub-tree, … )

                                    ROMAN NERUDA: EVA1 - 2023/2024
Crossovers
• Swap two subtrees
• Uniform crossover – GPUX (Poli, Langdon)
   • At early stages GPUX swaps large subtrees, as the population converges the
     operator becomes more and more local.,
   • Identify the common region C between two trees. Each node in C is
     considered for crossover with a constant probability.
   • Nodes in the interior of C are swapped without affecting the subtrees rooted
     at these nodes.
   • Nodes on the boundary of C - their subtrees are swapped.

Bloat of GP programs
• Programs in GP have tendencies to grow in size - bloat
• In nature, the extensive growth hits some physical limit that prevents
  excesses
• In GP we must fight bloat explicitly:
   • Limit tree size (no. of nodes), limit tree depth:
      • Penalize it as a negative term in fitness
      • Or, check and repair/eliminate new individuals
   • Anti-bloat operators:
      • Watch mutation and crossover so that do not enlarge much
      • Or, special mutations making trees smaller

Variations of tree-based GP
  • Homologous crossover – tries to preserve the position of genetic material in
    both parents
  • Identify common region in both parents – going from root, check for nodes
    with same parity (not necessarily the same function)
     • One-point crossover – choose crossover points from this common region
     • Uniform crossover – iterate through common region and choose a node (with a subtree
       if there is) at random from either parent
  • Context preserving crossover – identify coordinates of nodes (a sequence of
    directions in nodes on path from root)
     • Strong – allow crossover only on nodes with same coordinates
     • Weak – choose one node in one parent, and any subtree of node with the same
       coordinates in the second parent

Grammatical evolution (GE)
• Consider a (context free) grammar
   • a list of (numbered) rules
   • containing non-terminal and terminal symbols
   • with initial symbol
• By applying the rules, one finally creates a valid word in the language
  described by the grammar
• This can be represented by a derivation (parse) tree
• And, the sequential application of rules can be represented by a
  sequence of their numbers
Grammar and 2 derivation trees
GE – genotype and phenotype
• We have a fixed grammar
• Genotype is linear – a variable-length list of integers representing
  rules of the grammar to be applied
• To make encoding robust, a modulus operation is used to get rule
  number from (any) integer
• From genotype we get derivation sequence and a derivation tree.
• Phenotype is a syntax tree obtained from derivation tree by
  reduction.
GE wrap-up
• The genome is linear
   • we can use standard GA operators for evolution
• The genome maps into GP tree in a simple way
   • The MOD operator
   • Some technical issues to prevent large trees to be derived
       • wrap up operator that fires after limit size is reached
       • Low fitness for infeasible individuals
       • Repair mechanisms (after size limit, remove non-terminal expanding rules from the grammar)
• The genetic operators are not “local”
   • Small change in genotype can produce big change in the tree
• Grammatical swarm – PSO used for search

Nash
• A strategy s is dominant for agent i, if it gives better or the same
  result than any other strategy of an agent i against all strategies of
  agent j
• Strategies si and sj are in Nash equilibrium, if:
   • If agent i plays strategy si, agent j does best with strategy sj
   • If j plays sj, i does best with si
• Or, si and sj are the best mutual answers to each other
• These are called pure strategies

• Nash theorem: Every game with

Tuning vs. control
• EA has various parameters (population size, probability of operators,
  tournament size, elitism rate, ...)
• Common practice is to tune those parameters for a task at hand
   • Trial and error, grid search
   • Experience and good luck
• They are not independent & it is usually not possible to do exhaustive
  search really
• One possible solution is to not consider them static but dependent on
  time or other algorithm properties (e.g. fitness variance in
  population), and change them – control.
How?
• Fixed strategy
   • Time-dependent change of parameter
   • Deterministic
       • Decrease mutation probability 0.1% each generation
   • Stochastic
       • Simulated annealing
• Adaptive strategy
   • Based on information about the quality of solution, statistical properties of
     population, …
• Self-adaptive
   • Evolution of evolution
   • Mutation variances in genome of ES
Ex 1: Representation
• Adaptive change of representation (encoding of individual) based on
  population diversity:
   • GA with binary encoded real numbers, unknown precision is needed, so start
     with small number of bits per real
   • Run GA iteratively, every run is stopped when population diversity goes
     bellow 1
      • Measured by Hamming distance between the best and the worst individual in the
        population.
   • Save the best individual as reference, and run GA again
   • If the second run produces the same best individual, increase number of bits
     per real and start again
Ex 2: Mutation
• Gaussian mutation of real vectors:
   • x(t+1) = x(t) + N(0,s), where s is variance
• Deterministic change:
   • s(t) = 1 – 0.9 (t/T), where t=0, ... T
• Evolutionary strategies – first kind:
   • Heuristic observation from Berlin – the optimal success rate of mutation is
     1/5,
       • If the current rate is bigger, increase s about 10%,
       • If the current rate is smaller, decrease s about 10%
• Evolutionary strategies – second kind (self-adaptation):
   • Put s (for every x(t)) into the genome and evolve
Ex 3: Selection
• Boltzmann tournament:
   • Probability that the worse individual can win will depend exponentially on the
     ratio of fitness difference and temperature
   • Temperature decreases with time
   • If we stuck in local optima, increase the temperature
• Simulated annealing as local search:
   • Like hill climbing, but with Boltzmann probability of acceptance of worse
     solution
Ex 4: Population
• Indirect control of population size depending on the fitness of
  individuals
   • When new individual is generated, we define its life span proportional to its
     fitness
   • After the defined number of generations, the individual dies
   • Better individuals live longer, thus the system supports spread of successful
     individuals
   • Population size is thus only a derived, dynamic, and not so important thing

Let us simplify the (already simple) plain
vanilla GA - SGA
• Random initial population of length l binary strings x
   • Compute fitness f(x)
   • Repeat until new population is filled:
      • Select 2 individuals,
      • Cross them over with probability pc
      • Discard one of them (!) <- this is the simplification
      • Mutate each bit with probability pM
      • Insert new (one) individual to new population
• Repeat until a good enough individual x is found
Formalize the SGA
• Each binary string is represented by a number from 0..2l
   • 00000111 is 7
• Population in time t is represented:
   • By two vectors: p(t) a s(t) of lenght 2l
   • pi (t) represents the part of population t occupied by a string (relative
     frequency) – simplex
   • si (t) is probability of selection of string i
• p(t) defines the population composition
• s(t) defines selection probabilities
 The capital G operator
• We have fitness f, define matrix F(i,j):
    • F(i,i) = f(i); F(i,j) = 0 pro i<>j
• Then s(t) = F p(t)/(Σ F(j,j) pj(t))
    • (that’s in fact a definition of fitness-proportional selection)
• Our dream is to define operator G that would realize the SGA iteration:
    • i.e. p(t+1) = G p(t), or similarly s(t+1) = G s(t)
• If we have G, we iterate it from initial population, and we know everything
  about SGA
• Let us decompose G = F°M (F fitness, M mutation and crossover - mixing)
First let G=F
• E(x) expected value
• E(p(t+1)) = s(t)
• s(t+1) ~ F p(t+1) (just multiplicative constant c)
• Thus: E(s(t+1)) ~ F s(t)
   • In case of (small) finite population, the statistical errors can cause deviations
     from expected values E(.)
   • The bigger population, the smaller deviation
   • Infinite populations are exact, albeit a bit impractical
Now let G=M
• M is a recombination operator (including both crossover and
  mutation)
• The derivation requires some probability skills and lots of time:
    • Let us use a handy function r(i,j,k)
    • r(i,j,k) ... Probability that offspring k is created from parents i and j
    • When we have r(i,j,k), we can compute p(t+1)
    • Well, one part of vector after another, and also in expected values, but that’s
      why we now consider infinite populations:
• E(pk(t+1)) = ΣiΣj si(t) sj(t) r(i,j,k)
R(i,j,0)




• Derivation of r(i,j,k) is possible, this is r(i,j,0)
Results
• SGA works by applying G to each population in time, it is a dynamical
  system, and vectors p(t) or s(t) are points of the trajectory of such a
  system.
• What are the fixed points of G? (well, that exactly we still do NOT
  know)
   • Fixed points of F are populations consisting only of copies of the element with
     the highest fitness from the initial population
   • (The only) fixed point of M: identical probabilities s (or, the same relative
     frequencies of individuals p)
   • Combination of shaking by M and focusing by F - punctuated equilibria
     (known from biology)
Finite populations
• Markov chains:
   • Stochastic process in discrete time
   • System has states, the probability of going from one state to another depends
     only on the current state (no memory of previous states)
   • Table of transition probabilities between all states represents a complete
     description of such a system
• Now, let us define SGA over finite populations as Markov chain

while (not stoppingCondition())
  sNeighborhood ← getNeighbors(bestCandidate)
  bestCandidate ← sNeighborhood[0]
  for (sCandidate in sNeighborhood)
      if ( (not tabuList.contains(sCandidate)) and (fitness(sCandidate) > fitness(bestCandidate)) )

  end
  if (fitness(bestCandidate) > fitness(sBest))

   • Random swaps of two cities
   • Take better
   • Remember good visited solutions in taboo list
Tabu wrap-up
• Tabu principles used in many applications, like TSP, vehicle routing,
  DNA sequencing
• Pros
   • Escapes local optima
   • Avoids cycles and repeating solutions
   • Supports exploration
   • Can be used in discrete and continuous domains
• Cons
   • Takes time, increases number of iterations
   • Many parameters to tune
Scatter search
• The motivation was to improve global search by focusing on diversity
  of individuals
• Global population based meta-heuristics
• Proposed originally for solving hard combinatorial optimization
  problems
• The idea is to improve diversity of the population by means of the so-
  called reference set
Scatter search principles
• Algorithm:
   • Generate initial population P(0)
   • Select reference set R(0) as subset of P(0)
• Cycle in time :
   • Generate new candidate solutions P(t) by arithmetic crossover of individuals
     from R(t-1)
   • Apply local changes to P(t)
      • mutation
      • hill-climbing
      • tabu search
   • Update R(t) by (some) members of P(t)
Scatter parts
Diversification generation and improvement methods
while (stopping criteria not satisfied)
       Reference set update method
       while(new reference solutions) {
              Subset generation method
              Combination method
              Improvement method
              Reference set update method
       Rebuild reference set
end
Scatter parts
• Diversification – smart diverse population initialization
   • best results combine diversity and fitness
• Improvement – local search improving the fitness of one individual by
  mutations
• Reference set update – blend of high fitness and diverse individuals
• Subset generation – typically all possible pairs of individuals
• Combination – crossover of pairs, arithmetic, permutation, …
Reference set
• Can be created and updated in various ways
• Criterium to be in R is typically some combination of good fitness and
  diversity (members of R have to be good and not similar to each
  other)
• maximize minimal distances of newly added x from the rest of R
• Can be updated:
   • incrementally (1 or more individuals per population),
   • Or completely renewed every population,
   • Or created in the inner cycle, new individuals are already members of R and
     recombination is performed with them.
Scatter search wrap-up
• Evolutionary algorithm that explicitly supports diversification of
  individuals
• Exploration capabilities
• Can be tailored for limited number of fitness evaluations
• Implemented many times
   • e.g. OptQuest is a black-box global optimizer for problems with expensive
     objective function
Novelty search
• Lehman, Stanley, 2011 - Abandoning Objectives: Evolution through
  the Search for Novelty Alone
• Fitness-based search can be “deceiving”
• Leading to local optima
• Diversity of solution is important
• Diversity can be the objective
• Search for behavioral novelty (only!)
• Inspired by previous research in theory of GA and open-ended
  artificial life simulations
Deception
• Goldberg, 1987 – building block hypothesis has a problem – deceptive
  fitness
• such a fitness where smaller building blocks actually do not allow for
  global optimum when combined
• Some proposed the deception as a measure of EVA problem difficulty
  (some disagreed)
• The important motivation is that for deceptive problems, there is not
  a clear trajectory towards global optimum
The search for novelty
• Originated in evolutionary robotics
• Now successful in reinforcement learning
• Typically efficient in tackling hard problems with complex search
  space
• Support from natural evolution
   • No clear trajectories
   • No smooth transitions
Sparseness
• The key idea – define behavior space, the space of unique behaviors
  (phenotypical)
• Then, characterize how far away is a solution from the population and
  predecessors
• Define metrics to identify sparseness in behavior space
• Areas with dense clusters of visited points are less novel than sparse
  areas, and therefore rewarded less.
• Sparseness is a sum of distances of a point from its k-nearest
  neighbors
Algorithm
• Keep permanent archive of novel individuals
• Sparseness is computed from current population and the archive
• If the individual sparseness is high above some threshold, it enters
  the archive
• The new thing is using the novelty measure only
• Combined with NEAT
   • Robot in maze, experiment
   • Bipod evolution experiment

Population based search inspired by
Ants and ACO
• M. Dorigo (1991)
• Group search inspired by highly-evolved social behavior of ants
• No explicit crossover or exchange of information
• Indirect communication via pheromone marks
• Used in hard optimization problems, first on graphs (shortest path,
  routing, …)
• Extensions for continuous optimization
• EVA (is it?) meet multi-agent systems
Example: Steels’ Mars explorer
• The goal is to collect precious rock samples on distant planet by a
  swarm of robotic explorers

• Means:
• The base transmits a navigation signal
• Communication is not necessary, it is sufficient to detect a gradient of
  the signal
• Every robot has radioactive crumbles for indirect communication with
  other robots
Random walk and return of one robot
• R1: if detect obstacle then change direction
• R2: if carrying sample and at the base then drop sample
• R3: if carrying sample and not at the base then travel up gradient
• R4: if detect a sample then pick sample up
• R5: if true the move randomly

• Priority!
Second iteration: better exploration
 • What to do if I carry a sample:
 • R6: if carrying a sample and at the base drop sample
 • R7: if carrying a sample and not the base then drop 2 crumbs and
   travel up gradient
 • R8: if sense crumb then pickup 1 crumb and travel down gradient

 • Priority
ACO general scheme
• Convert the problem to finding a shortest path in weighted graph
   • Ants are then agents searching for solution
• Each edge will carry a pheromone information
   • The more pheromone, the “better” part of solution
• Algorithm iterates:
   • Stochastically generate solution (order of edges) for each ant
   • Sometimes perform local search on paths – daemon actions
   • Compare the solutions w.r.t fitness
   • Update pheromones on edges
AS – Ant system
• The original algorithm by Dorigo, solves TSP
• Ants are travelling from city to city, searching for optimal path, adding
  cities to their path:
   • Choose from cities not in your path
   • Probability of city C choice depends on:
      • The distance of the city C from current city
      • The pheromone level on the edge between C and current
• Pheromone updates:
   • All pheromone evaporates with some small rate
   • If ant travels the edge, pheromone is increased proportionally to the fitness
     of this ant solution
ACS – ant colony system
• Improved version competitive with TSP solvers
• Inspiration from q-learning
• Main changes:
   • AS updates pheromones using all solutions, in ACS, only the best solution is
     used to globally update pheromones
   • ACS introduces local pheromone updates: Each time ant travels the edge, the
     pheromone evaporates a bit
   • The choice of the next city has two versions:
      • The AS choice with some probability (exploitation)
      • Choice based on pheromones only (exploration)
Other ACO improvements
• Elitist – only globally best updates pheromones (implemented in ACS)
• Rank-based – group of N best solutions is used for update, the rate
  depends on their fitness
• Min-Max – levels of pheromones are kept within a range
• Continuous optimization:
   • Discretize the space into interval-based subspaces
   • Pheromone mechanism is used to guide search into better sub-intervals
ACO wrap-up
• Inspiration from social insect:
   • Decentralized control
   • Emergence of behavior
   • Indirect communication
• Close relation to reactive architectures of intelligent agents – Brooks
  subsumption architecture
• The advantage over other approaches is that they can optimize in
  dynamic environments
• Used in practice: TSP, vehicles routing, internet, protein folding, image
  edge detection, …
CMA-ES
Covariance matrix adaptation, black-box optimization
Black-box optimization
• Minimize an objective function (cost, or fitness function) f : Rn→R
  x→f(x) .
   • We do not state the objective of searching for a global optimum, as this is
     often neither feasible nor relevant in practice.
• Black box optimization:
   • function values of evaluated search points are the only accessible information
     on f (no access to gradient)
   • the search points to be evaluated can be freely chosen.
   • the search costs is the number of executed function evaluations.
BBO how-to zoo
• Stochastic Searches:
   • Evolutionary Algorithms,
   • Evolutionary strategies,
   • Covariance Matrix Adaptation ES,
   • EDAs
• (Local) Heuristics:
   • Simulated Annealing
   • Hill Climbing
   • Downhill Simplex
BBO stochastic search principle
• The algorithm maintains a probability distribution Pθ(x)
• It is used for efficient sampling of function values
• In each iteration it takes n samples
   • {xi; i=1..n} from distribution Pθ(x)
• Each xi is evaluated → we get data {(xi,f(xi)); i=1..n}
• That data is used to update θ

Distribution is:
• The parameter θ is the only knowledge/information that is being
  propagated between iterations
• θ encodes what has been learned from the history
• θ defines where to search in the future
• Examples:
   • Evolutionary Algorithms: θ is a parent population

   • Simulated Annealing: θ is the “current point” and a temperature
CMA-ES
• θ = (xˆ,σ,C,pσ,pC)
• Pθ(x) = N(x|mean(x),σ2C)
• where C is the covariance matrix of the search distribution
• The θ maintains two more pieces of information:
   • pσ and pC
   • capture the “path” (motion) of the mean(x) in recent iterations
• Rough outline of the θ-update:
   • Let Dʹ = bestOfμ(D) be the set of selected points
   • Compute the new mean(x) from Dʹ
   • Update pσ and pC proportional to mean(x)k+1 − mean(x)k
   • Update σ depending on |pσ|
   • Update C depending on pcpc⊤ (rank-1-update) and Var(Dʹ)
