   recommended so that all attributes can have equal

Nominal attributes

 Sometimes, we need to transform nominal attributes
   (e.g., colors, kinds of fruits, etc.) to numeric attributes

  => Transform nominal attributes to binary attributes:

         · Let the number of values of a nominal attribute be v.
         · Create v binary-valued attributes to represent them.
         · If a data instance for the nominal attribute takes a particular

           value, the value of its binary attribute is set to 1, otherwise
           it is set to 0.
         · The resulting binary attributes can be used as numeric
           attributes, with two values, 0 and 1.

     · Apple, Orange, and Pear

Range, Quartiles and Outliers

 The range of a set of data is the difference between the highest and
   the lowest value in the set.

 The quartiles Q1, Q2, Q3 split the data into four parts

                   Q1       Q2                  Q3

Lowest value                                              Highest value

              25%      25%      25%                 25%

     · 25% of the observations should have a value less than the lower quartile, Q1
     · 50% of the observations should have a value below the median, Q2 , and
     · 75% of the observations should have the value below the upper quartile, Q3

 Interquartile range = upper quartile ­ lower quartile

 An outlier is an extreme value that lies outside the
   overall pattern of data.

 The following rule is often used to identify outliers:

   An outlier is any value, which is

      · Greater than the upper quartile + 1.5 · interquartile range or
      · Less than the lower quartile - 1.5 · interquartile range

Regression analysis

 ~ determine the relationship of variable Y to other (one or more)
      variables X1,...,Xm

Reasons for regression analysis:

 1. It is very costly to obtain / measure the output values => predict
      the output based on the inputs that are easily available

 2. Input values are known earlier than the output => estimate the
      output

 3. Controlled input values might help find correct behavior of the
      output

 4. There can be a causal relationship between the input and output
      of a system => find this relationship

The k-medoids algorithm - Why select the representatives from D?

1. k-means clusters may be distorted by outliers

            => cluster representatives can be located in empty regions, unrepresentative of
                 most of the data points in that cluster

             => such representatives may lead to partial merging of different clusters
            Yet this problem can be resolved (at least partially ) with careful outlier handling

 2. it might be difficult to compute the optimal central representative for complex
    data, e.g., a set of time series of varying length

             => selecting representatives from the original dataset may be very helpful.

     the k-medoids algorithm can be defined virtually for any data type, as
        long as an appropriate similarity or distance function can be provided

The k-medoids algorithm:

   uses hill-climbing with the representative set S initialized to a set of points from D
   S is iteratively improved by exchanging a point from S with a data point from D

   Possible strategies for the exchange:

       1. try all |S||D| possibilities for replacing a representative in S with a data point
           from D and then select the best one => extremely expensive!

       2. use a randomly selected set of r pairs ,  for a possible exchange
           ( is from D,  is from the representative set S);
           the best of the r pairs is then used for the exchange.

          This solution requires time proportional to r |D| and is said to have converged when

           the objective function does not improve, or if the average objective function
           improvement is below a user-specified threshold in the previous iteration.

  slower than the k-means method but applicable to various data types

   a scalable version represents the CLARA/CLARANS algorithm.

Scalable data clustering

The CLARA/CLARANS approach:

  in many clustering applications, the size of the data is very large

      the data cannot be stored in main memory and needs to reside on disk
      a challenge with constraints on the algorithmic design of the methods

  CLARA and CLARANS are scalable implementations of k-medoids

       inherit both the advantages and disadvantages of the base algorithm
       e.g., the CLARANS algorithm is easily generalizable to different data types

         (beyond numeric data), but it inherits the relatively high computational
         complexity of k-medoids

  The choice of the most suitable algorithm depends on the application
    at hand!

I. MRÁZOVÁ: DATA MINING  86
Scalable data clustering (2)

The generic k-medoids approach:

  works with a set of representatives
  iteratively attempts to exchange a medoid with a non-medoid to improve

     the clustering quality
  allows flexibility in deciding how to execute the exchange

The CLARA method (Clustering LARge Applications):

   based on a variant of the k-medoids method - Partitioning Around Medoids (PAM)
   all possible k (n-k) pairs of medoids and non-medoids are tested for an exchange
   the pair with the best improvement of the objective function is then exchanged
   Exchanges are performed until the algorithm converges to a locally optimal value
   for each iteration, the exchange process requires O(k n2) distance computations,

     i.e., O(k n2 d) time for a d-dimensional data set

      => RATHER EXPENSIVE!

I. MRÁZOVÁ: DATA MINING                                                              87
Scalable data clustering (3)

The CLARA method - continued:

  Complexity can be reduced by applying the algorithm to a smaller sample
    set of size f n to find the medoids (f is a sampling fraction, f << 1)

  The remaining (non-sampled) data points are assigned to the medoids
     found in the smaller sample.

  The above approach is applied repeatedly over independently chosen
    samples of data points of the same size f n.

  The best clustering over all these independently chosen samples is then
     selected as the optimal solution.

  For small values of f, CLARA can be orders of magnitude faster
      the complexity of each iteration is then: O(k f2 n2 d + k (n-k))

  The main problem with CLARA occurs when the preselected samples do
     not include a good choice of the medoids!

Scalable data clustering (4)

The CLARANS approach:

  ~ Clustering Large Applications based on RANdomized Search

   works with the full data to avoid the problem with incorrectly preselected samples
   iteratively tests exchanges between random medoids with random non-medoids.

       after each trial, it is checked if the quality improves.
       if the quality improves, the attempted exchange is made final
       otherwise, the number of unsuccessful exchange attempts is counted
       a local optimal solution is said to have been found when a user-specified number

          of unsuccessful attempts MaxAttempt has been reached.

   the entire process of finding the local optimum is repeated for a user-specified
     number of iterations, denoted by MaxLocal.

   The clustering objective function of each of these MaxLocal locally optimal solutions
     is evaluated.

   The best among these local optima is selected as the optimal solution.

 CLARANS explores a greater diversity of the search space than CLARA !

Scalable data clustering (5)

The CURE approach:

  ~ Clustering Using Representatives - an agglomerative hierarchical algorithm

    very fast and able to discover clusters of an arbitrary shape (unlike, e.g., CLARANS)

 The overall process can be described by the following steps:

    1. Sample s points from the database D of size n.
    2. Divide the sampled s points into p partitions of size s/p each.
    3. Cluster each partition independently using the hierarchical merging to k' clusters in

         each partition. The overall number k' · p of clusters across all partitions is still larger
         than the user-desired target k.
    4. Perform hierarchical clustering over the k' · p clusters derived across all partitions to
         the user-desired target k.
    5. Assign each of the (n-s) non-sample data points to the cluster containing the closest
         representative.
